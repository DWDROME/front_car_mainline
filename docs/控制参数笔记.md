# 控制参数笔记

这份笔记记录 `front_car_mainline` 当前控制参数的位置、加载顺序和每帧调用关系。这里说的是当前真实主链，不记录旧的环境变量调参旁路。

## 1. 参数来源顺序

控制参数只有这一条来源链：

```text
code/core/config.hpp 默认值
-> 启动时 load_control_config(path) 读取外部配置覆盖
-> control.cpp 每帧通过 control_config() 取当前参数
-> solve_control_input_with_feedback(input, fb, ctrl) 计算 duty
-> drive_output_apply(ctrl) 输出到电机
```

外部配置路径由 `code/app/main.cpp` 决定：

```text
FRONT_CAR_CONFIG 环境变量非空：使用 FRONT_CAR_CONFIG 指定的路径
否则：使用 /root/front_car_mainline.yaml
```

入口代码位置：

```text
code/app/main.cpp
-> read_env_text("FRONT_CAR_CONFIG", "/root/front_car_mainline.yaml")
-> load_control_config(path)
```

## 2. 参数文件位置

默认值：

```text
code/core/config.hpp
```

本地示例配置：

```text
front_car_mainline.yaml
```

板端默认配置：

```text
/root/front_car_mainline.yaml
```

可用环境变量指定其他路径：

```bash
FRONT_CAR_CONFIG=/path/to/front_car_mainline.yaml ./front_car_mainline
```

如果外部配置文件不存在，会打印警告并继续使用 `config.hpp` 默认值：

```text
ConfigWarn: <path> not found, using config.hpp defaults
```

## 3. 配置格式

解析代码在：

```text
code/core/config.cpp
```

当前解析器只支持简单的 `key: value`，不是完整 YAML 解析器。

支持：

```yaml
target_rps: 4.0
outer_kp: 0.03
left_speed_kp: 1.25
```

支持 `#` 注释：

```yaml
outer_kd: 0.0  # 图像误差抖动时不要轻易打开
```

不支持嵌套：

```yaml
control:
  target_rps: 4.0
```

未知 key 会打印：

```text
ConfigWarn: unknown key '<key>'
```

非法数值也会打印警告，并保留该字段原来的默认值或已加载值：

```text
ConfigWarn: invalid value for '<key>': '<value>'
```

## 4. 当前支持的 key

这些 key 来自 `code/core/config.cpp::set_field()`，字段名必须完全一致。

```text
control_period_ms

target_rps
element_target_rps
speed_target_rps

left_speed_base_percent
right_speed_base_percent
left_speed_kp
right_speed_kp
left_speed_ki
right_speed_ki

wheel_track_m
encoder_gear_diameter_m

gyro_raw_to_rad_s
imu_yaw_feedback_enabled

outer_kp
outer_kd
outer_sign
straight_error_threshold
straight_turn_scale
max_target_yaw_rate

yaw_kp
yaw_ki
max_yaw_rate_correction

rps_filter_alpha
yaw_rate_filter_window

```

`control_period_ms` 仍然只从配置文件进入控制链。实车 `live()` 入口会把它限制在 `1..100ms`，越界时打印 `ConfigWarn`；不再读取同名环境变量作为旁路覆盖。

## 5. 每帧如何调用

实车闭环主入口是：

```text
solve_control_input_with_feedback(input, fb, ctrl)
```

典型每帧顺序：

```text
drive_output_read_feedback(&fb)
-> encoder_total += (left_count + right_count) / 2
-> tracking_process_frame(rt)
-> control_input_t(line_found, guide_error, element_active, stop_line)
-> solve_control_input_with_feedback(&input, &fb, &ctrl)
-> drive_output_apply(&ctrl)
```

`solve_control_input_with_feedback()` 内部进入 `control.cpp::solve()`，然后读取当前参数：

```cpp
const control_config_t &c = control_config();
```

之后整帧都通过 `c.xxx` 使用参数。

无反馈/离线入口是：

```text
solve_control_input(input, ctrl)
```

它会构造空的 `control_feedback_t`，主要用于无编码器和无 IMU 反馈的路径；实车闭环优先看 `solve_control_input_with_feedback()`。

## 6. 参数对应的控制阶段

### 6.1 目标速度

```text
target_rps：普通巡线中心目标速度
element_target_rps：十字/环岛内中心目标速度
speed_target_rps：左右轮 FF 前馈缩放参考
```

使用位置：

```text
control.cpp
-> center_rps = target_rps / element_target_rps
-> FF 用 speed_target_rps 做缩放参考
```

### 6.2 视觉外环

```text
outer_kp
outer_kd
outer_sign
straight_error_threshold
straight_turn_scale
max_target_yaw_rate
```

控制链：

```text
guide_error
-> outer_kp * err + outer_kd * derr
-> outer_sign
-> 直道小误差缩放
-> max_target_yaw_rate 限幅
-> target_yaw
```

注意：`target_yaw` 是视觉外环给出的目标角速度，不是最终 duty。

### 6.2.1 RT1064 舵机链和当前差速链边界

这段是后续对照参考版时的硬边界：RT1064 的 `pure_angle` 是舵机前轮角输入，当前 `front_car_mainline` 的 `guide_error` 是差速 yaw-rate 外环输入，不能把 `pure_angle` 公式机械塞进当前外环。

本地参考源码位置：`/mnt/e/longxin/RT1064_Code_ref/SJTU-AuTop-RT1064-Code`。

| 对照项 | RT1064 参考版 | 当前 `front_car_mainline` | 结论 |
| --- | --- | --- | --- |
| 控制参考点 | `main.c:375-401` 用 raw 车轮点 `(W/2, H*0.78)` 查 `mapx/mapy` 得到 `(cx, cy)`，再把最近中线点改成 `(cx, cy)` 后重采样。 | `atg_reference_mainline.cpp::atg_control_ref()` 直接使用 `rt->control_center_x`（默认 `CONTROL_CENTER_X`）和 `START_HIGH`，不做 raw 车轮点查 IPM。 | 这部分描述的是中线预瞄参考点，不是舵机/差速控制器本身。 |
| 角度误差 `error` | `main.c:408-420` 计算 `error=-atan2f(dx, dy)` 和 `error_near`，其中 `dy = cy - rptsn[aim_idx][1] + 0.2 * pixel_per_meter`，但当前激活的舵机路径没有使用这两个值。 | `atg_reference_mainline.cpp::atg_lookahead_error()` 按 `LOOKAHEAD_DIST` 选 ATG `rptsn` 中线预瞄点，输出 heading-style `guide_error=-atan2(dx, dy + forward_bias)`。 | 当前 `guide_error` 更接近 RT1064 的 `error` 形状，而不是 `pure_angle`。 |
| 舵机纯跟踪 `pure_angle` | `main.c:428-444` 用 `pure_angle=-atanf(pixel_per_meter * 2 * 0.2 * dx / dn / dn) / PI * 180 / SMOTOR_RATE`，再进 `pid_solve(&servo_pid, pure_angle)`，限幅后通过 `smotor1_control(servo_duty(SMOTOR1_CENTER + angle))` 输出。`SMOTOR_RATE` 在 `smotor.h` 说明是前轮转角和方向舵机转角比例。 | 当前没有舵机 `servo_pid`、`SMOTOR1_CENTER + angle` 或 `servo_duty` 控制链。`guide_error` 在 `control.cpp:231-258` 进视觉外环 PD，输出 `target_yaw`。 | `pure_angle` 的消费者和物理执行器不同，不能直接替换当前 `guide_error`。 |
| 当前差速外环 | 无直接等价路径；RT1064 输出前轮/舵机角。 | `guide_error -> outer_kp/outer_kd/outer_sign -> target_yaw`，之后 `yaw-rate PI -> yaw_cmd`。 | 如果要引入曲率/纯跟踪，必须重新定义差速外环输出为 yaw-rate/curvature，不是照搬舵机角公式。 |
| 差速运动学 | 无直接等价路径。 | `yaw_cmd * wheel_track_m * 0.5` 得到左右轮线速度差，再换算 `target_l/target_r`。 | 当前扭动问题要先查 `guide_error` 抖动、`outer_kp`、`straight_turn_scale`、IMU yaw 内环和轮距/轮径标定，不能只从 RT1064 `pure_angle` 推公式。 |
| 外部运动学辅证 | Ackermann/自行车模型 pure pursuit 常输出前轮角 `delta`，这和 RT1064 舵机链一致。参考：<https://thomasfermi.github.io/Algorithms-for-Automated-Driving/Control/PurePursuit.html>。 | MathWorks Pure Pursuit block 对 car-like 或 differential-drive 输出 linear velocity + curvature，并说明 angular velocity 可由 curvature 乘 linear velocity 得到。参考：<https://www.mathworks.com/help/robotics/ref/purepursuit.html>。 | 外部资料只支持“执行器输出不同”的边界判断。若以后做差速 pure pursuit，应输出 curvature/yaw-rate 后接当前 `target_yaw/yaw_cmd` 合同，而不是塞入 `pure_angle`。 |

固定结论：

```text
可以参考：raw 车轮点 -> IPM 控制参考点、heading-style error 的符号和前向偏置。
不能照搬：pure_angle -> servo_pid 这一段，因为当前车是 guide_error -> target_yaw -> yaw_cmd -> 左右轮差速。
未来若改差速 pure pursuit：必须重新定义 curvature/yaw-rate 输出和单位，再作为控制任务审计。
本次 RT1064 ring 主链修正没有改 `code/core/control.cpp`、控制参数或 `lookahead_error()` 公式；唯一可能影响控制输入的是 ring 状态进入时机按 RT1064 直接入口恢复后，元素速度/选线会按新的 `rt->ring.kind/state` 生效。
```

| 参考版怎么样 | 当前代码差异 | 我修改什么 | 原因 | 不是兜底的证据 |
| --- | --- | --- | --- | --- |
| RT1064 `main.c:408-444` 同时算 `error` 与 `pure_angle`，但激活路径是 `pure_angle -> servo_pid -> smotor1_control`。 | 当前是 `atg_reference_mainline.cpp::atg_lookahead_error()` 发布 `guide_error`，`control.cpp` 把它变成差速 `target_yaw/yaw_cmd`。 | 本节只记录对照边界，不改运行时公式。 | 防止后续把“参考版纯跟踪舵机角”误当成当前差速 yaw-rate 外环合同。 | 没有新增缓存、阈值、平滑、上一帧复用或控制输出保持；运行时行为不变。 |
| 外部 pure pursuit 资料把 Ackermann `delta` 和 differential `curvature/yaw-rate` 分开。 | 当前工程没有舵机消费者，只有 `guide_error -> target_yaw -> yaw_cmd -> target_l/r`。 | 补充外部运动学辅证和未来改法边界。 | 避免把“纯跟踪公式”当成单一公式，不看执行器和输出单位。 | 仍是文档研究；没有改变 `lookahead_error()`、`control.cpp` 参数、限幅或输出。 |
| RT1064 `circle.c` 恢复的是 ring 状态入口和阶段切换，不定义当前差速车的控制器参数。 | 当前控制器仍是 `control.cpp` 的 `guide_error -> target_yaw -> yaw_cmd -> target_l/r`，但 ring 进入后会让元素选线/元素速度按 `rt->ring.kind/state` 生效。 | 只记录这条间接边界；不改控制代码。 | 防止把 ring 合同恢复误读成控制器被重写。 | `code/core/control.cpp`、控制参数和 `lookahead_error()` 公式无 diff；没有新增滤波、限幅、PID、旧误差保持或 duty 保持。 |

### 6.3 yaw-rate 内环

```text
imu_yaw_feedback_enabled
max_yaw_rate_correction
yaw_rate_filter_window
```

控制链：

```text
actual_yaw_rate_mrad_s
-> yaw_avg()
-> yaw_now
-> target_yaw - yaw_now
-> yaw PI
-> max_yaw_rate_correction 限幅
-> yaw_cmd
```

如果 IMU 反馈无效、`imu_yaw_feedback_enabled == 0`，或者 `max_yaw_rate_correction <= 0`，则本帧直接使用：

```text
yaw_cmd = target_yaw
```

### 6.4 差速运动学

```text
wheel_track_m
encoder_gear_diameter_m
```

控制链：

```text
center_rps + yaw_cmd
-> center_mps / diff_mps
-> target_l / target_r
```

注意：轮距和编码轮直径不准，会直接影响同一个 `yaw_cmd` 下的左右轮目标速度差。

### 6.5 左右轮 FF + PI

```text
left_speed_base_percent
right_speed_base_percent
left_speed_kp
right_speed_kp
left_speed_ki
right_speed_ki
rps_filter_alpha
max_duty_percent
```

控制链：

```text
encoder count
-> count_to_rps()
-> rps_filter_alpha 低通
-> g_left_rps / g_right_rps
-> target_l/r - g_left/right_rps
-> base_percent FF + speed PI
-> duty_l / duty_r
-> max_duty_percent 限幅
```

注意：`drive_output.cpp` 里仍有硬件安全上限，控制层 `max_duty_percent` 不是唯一限幅。
