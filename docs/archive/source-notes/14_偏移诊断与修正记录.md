## 2. 当前已知的修正点

### 2.1 IPM 中心校准

| 项目 | 旧方案 | 当前方案 |
|------|--------|----------|
| 中心参考 | 图像半宽 `80`（硬编码） | `vehicle_raw_ref_x: 80.0`（YAML 配置） |
| 角度偏置 | `guide_error_bias_deg: 13.0` | `guide_error_bias_deg: 0.0`（已废弃） |

**为什么改**：旧方案用角度 bias 掩盖 IPM/车体投影问题，相当于"歪了就加个修正值"。
新方案用几何参考点 `vehicle_raw_ref_x` 从源头对齐，不再需要角度补偿。

**怎么检查**：见第 4 节"直道偏移检查"。

### 2.2 编码器方向修正

```text
code/drivers/drive_output.cpp:139  左轮取反（-1）
code/drivers/motor_pulse.cpp:22    左编码器 sign = -1
code/drivers/motor_pulse.cpp:23    右编码器 sign = +1
```

**为什么改**：硬件安装时左右编码器方向相反，必须在外设层统一修正。
控制层拿到的已经是"前进为正"，不再重复处理。

**怎么检查**：停车后看 `report` 里的 `encoder_total` 是否随前进递增。

### 2.3 外环方向修正

```yaml
outer_sign: -1.0   # 2026-06-13 实车确认：+1.0 实跑反向
```

**为什么改**：`control.cpp` 注释说"yaw_cmd>0=右轮快=左转"，但实际执行器方向相反。
`outer_sign=-1.0` 修正了这个方向。

**怎么检查**：直道上 `guide_error` 为正时，车应该向右转（补偿左偏）。

### 2.4 IMU 零漂采样

```text
code/drivers/imu_feedback.cpp
启动时采样 48 次，取均值作为零漂
```

**为什么改**：陀螺仪有固定零漂，不扣掉会导致 yaw 积分持续偏移。

**怎么检查**：启动日志里 `ImuReady` 行的 `bias_x/y/z` 值应该稳定（同一温度下变化 <5）。

### 2.5 编码器 → ATG 距离换算

```text
code/app/runners.cpp
把 LS2K 的 4096-count/rev 编码器增量换算成 ATG 的 ENCODER_PER_METER=5800 距离单位
```

**为什么改**：ATG 圆环退出距离门（4500/7500）是按 5800 count/m 标定的。
直接喂 4096-count 会让距离门缩短一个数量级，圆环还没出去就退出了。

**怎么检查**：圆环日志里 `total_distence` 应该随实际行驶距离线性增长。

## 3. 待实车验证的问题

### 3.1 半十字偏左

**现象**：进入 `CROSS_HALF` 后，车明显向左偏。

**可能原因**（三种，需要日志区分）：

1. **远线点数很少**（`far_rpts*_num` 低）
   → 问题在搜索窗口/阈值/IPM 几何

2. **远线有但 L 点没命中**（`far_Lpt*_found` 为 0）
   → L 点判定太严或锚点不适配

3. **远线和 L 点都有，但车偏左**
   → 半十字控制参数不合适（`aim_distance`、单边外扩、IPM 几何偏了）

**当前处理**：已推送 `CROSS_HALF` bounded relay（500ms 限时直行），防止停死。
偏左根因待实车跑一次后根据日志判断。

**诊断量**：

```text
far_rpts0s_num / far_rpts1s_num   远线点数
far_Lpt0_found / far_Lpt1_found   远线 L 点命中
track_type                        当前按左线还是右线外扩
rptsn_num                         最终工作线点数
guide_error                       偏移量（正=右偏，负=左偏）
```

### 3.2 直道巡线是否居中

**检查方法**：见第 4 节。

## 4. 实车偏移检查方法

### 4.1 直道偏移检查（最常用）

**场景**：车停在直道上，相机对着赛道。

**步骤**：

```bash
# 1. 从板端抓一张图
bash scripts/ipm_recalib_capture.sh

# 2. 跑审计
bash scripts/straight_baseline_audit.sh .diag/ipm_recalib/ipm_raw_640x360.png
```

**看什么**：

| 报告键 | 正常范围 | 异常说明 |
|--------|----------|----------|
| `guide_error` | 接近 0（±5° 以内） | 持续偏左/右说明 IPM 中心或预瞄有问题 |
| `atg_rptsn_num` | >30 | 工作线太短说明选线有问题 |
| `atg_lpt0_found` / `atg_lpt1_found` | 1 | 0 说明角点没找到 |
| `control_ref` x 坐标 | 接近 80 | 偏离说明 IPM 几何偏了 |

### 4.2 停车位置检查

**场景**：车停在赛道左侧（或右侧），看 `guide_error` 是否正确反映偏移。

**步骤**：

```bash
# 1. 抓图（车停在赛道左侧）
bash scripts/ipm_recalib_capture.sh

# 2. 跑审计
bash scripts/straight_baseline_audit.sh .diag/ipm_recalib/ipm_raw_640x360.png
```

**看什么**：

- 车偏左 → `guide_error` 应该为**正**（需要右转回中）
- 车偏右 → `guide_error` 应该为**负**（需要左转回中）
- 车居中 → `guide_error` 应该接近 **0**

如果方向反了，说明 `outer_sign` 或编码器符号有问题。

### 4.3 IPM 几何检查

**场景**：检查 IPM 投影是否正确。

**步骤**：

```bash
# 1. 抓图
bash scripts/ipm_recalib_capture.sh

# 2. 跑 IPM 几何审计
bash scripts/ipm_geometry_audit.sh .diag/ipm_recalib/ipm_raw_640x360.png
```

**看什么**：

| 检查项 | 正常 | 异常 |
|--------|------|------|
| IPM 预览直道 | 边界线近似竖直 | 明显倾斜 → 点选位置不好 |
| IPM 赛道宽度 | ~52px（0.45m × 116px/m） | 偏差太大 → 标定重做 |
| 中线不系统性偏移 | `control_ref` x 接近 80 | 持续偏左/右 → IPM 中心偏了 |

### 4.4 控制参数敏感度检查

**场景**：检查不同 `control_center_x` 下 `guide_error` 的变化。

**步骤**：

```bash
# 跑控制中心敏感度审计
bash scripts/straight_baseline_audit.sh .diag/front_car_capture_live_current.png
# 或指定多个 center 值
SMARTCAR_CENTER_SWEEP="60 80 100" bash scripts/control_center_sensitivity_audit.sh
```

**看什么**：

- `guide_error` 随 `control_center_x` 变化是否单调
- 如果 `guide_error` 在某个范围内跳变，说明预瞄点选在了角点附近

## 6. 心智模型：偏移从哪来

```text
摄像头 → 灰度图 → ATG 搜线 → IPM 投影 → 选线 rptsn → guide_error → 控制 → 电机
   │         │         │         │         │         │
   │         │         │         │         │         └─ outer_sign 方向
   │         │         │         │         └─ 预瞄点选择（lookahead_time_s）
   │         │         │         └─ IPM 中心（vehicle_raw_ref_x）
   │         │         └─ 搜索阈值（block_size/clip_value）
   │         └─ 图像质量（曝光、镜头畸变）
   └─ 相机安装角度、高度
```

每一层都可能引入偏移。排查时从最外层（控制参数）开始，逐层往里查。
